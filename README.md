# Тревел лента на Кинескопе

Локальный прототип вертикальной ленты из 10 роликов. Исходный список, снимок офферов и публичное оформление автора «Проверено Туту» лежат в `feed-data.js`: для каждого исходного ролика там хранится ID, а ссылка на воспроизведение собирается как `https://kinescope.io/<ID>`. Сами видео загружаются плеером Кинескопа. Загруженные через админку файлы хранятся в локальной `.local-data/uploads/` и воспроизводятся через встроенный HTML5-плеер.

## Локальный просмотр и админка

На GitHub Pages главная ссылка `https://nykval.github.io/tutu-tiktok/` открывает админку, а лента находится по адресу `https://nykval.github.io/tutu-tiktok/feed.html`. Публичная админка пока доступна только для просмотра: GitHub Pages не сохраняет изменения.

```bash
python3 dev_server.py
```

- Админка: http://127.0.0.1:8765/
- Лента: http://127.0.0.1:8765/feed.html

В админке есть разделы «Видео», «Авторы», «Товары», «Отчёты» и «Настройки». Для авторов и товаров доступны создание, поиск, редактирование и удаление. Товары можно скрывать и публиковать. Автора можно назначить ролику, товар — привязать к офферу. Выпадающие списки оформлены единым компонентом, иконки взяты из переданного набора uicons.

Ролик можно добавить по ссылке Кинескопа или загрузить MP4/WebM до 150 МБ, назначить автора, категорию, теги и постер. При редактировании ролика Кинескопа показывается полный адрес источника с возможностью открыть его; ID исходного ролика остаётся неизменным. Для ролика доступен один оффер из каталога товаров или с ручным вводом. Карточки можно искать и фильтровать; меню позволяет открыть предпросмотр, отредактировать, скрыть, опубликовать, скачать локальный файл или удалить добавленный ролик. Исходные 10 роликов можно редактировать и скрывать.

Отчёты собирают локальные события открытий роликов, лайков, кликов по офферам и времени просмотра после запуска этого сервера. Исторических данных и заказов Streamerce здесь нет. Таблицу можно выгрузить в CSV.

Изменения и загрузки сохраняются в `.local-data/` на этом компьютере. Директория не коммитится в Git. Сервер слушает только `127.0.0.1` и не имеет авторизации: **не выставляйте его в публичную сеть**. При запуске через обычный `python3 -m http.server` или на GitHub Pages лента работает с исходными данными, а админка недоступна для записи. Чтобы опубликовать изменения для всех пользователей, нужен отдельный сервер с хранилищем и авторизацией.

После правки `feed.js` или `feed.css` для GitHub Pages увеличьте версию `?v=` в `feed.html`, чтобы сбросить браузерный кеш. На локальном сервере достаточно обновить страницу.

Плеер на телефоне нужно проверять отдельно: первый ролик подготавливается на паузе с иконкой ▶. Нажатие запускает видео со звуком; следующие ролики воспроизводятся при листании. После свайпа следующий ролик стартует автоматически. Лента заранее подготавливает два следующих ролика и один предыдущий; только выбранный ролик воспроизводится. Если запуск не состоялся, лента повторяет попытку и показывает кнопку повтора при ошибке. Шкала прогресса поддерживает перемотку, при скрытии вкладки видео ставится на паузу.


## Производительность ленты

При открытии ленты первый выбранный ролик загружается на паузе: автозапуск отключён, поверх постера отображается кнопка ▶. После нажатия видео запускается со звуком, а следующие ролики воспроизводятся при листании. До первого нажатия переход к другому ролику также сохраняет паузу. Safari и WebView могут требовать действие пользователя: звук включается непосредственно при нажатии, без отложенного обработчика. Если запрос запуска зависает, появляется кнопка самого плеера. Качество подбирается автоматически с потолком 720p, на слабой сети — ниже. Принудительного переключения качества при старте нет. Для локальных загрузок качество определяется самим файлом.

Предзагрузка идёт последовательно: два ролика по направлению прокрутки и один с противоположной стороны. При экономии трафика, слабой сети или малом объёме памяти готовится один сосед. При буферизации приоритет получает активное видео. Незавершённые загрузки отменяются при уходе к другому ролику, а заменяемый iframe остаётся внутри удаляемого контейнера. При открытии предложения воспроизведение и предзагрузка приостанавливаются.

Для проверки времени используются атрибуты корневого элемента страницы: `data-first-playback-ms` (от запуска скрипта ленты до первого сигнала воспроизведения), `data-player-ready-ms` (создание плеера), `data-startup-ms` (от переключения до сигнала воспроизведения), `data-player-source` (`new`, `preloaded`, `cached`). Это события плеера, а не измерение вывода кадра на экран. Сравнивать нужно несколько запусков на одинаковых устройствах и соединениях; тесты в настольном браузере не заменяют проверку на iOS и Android.

Проверки: `node --test tests/feed-runtime.test.cjs` и `python3 -m unittest discover -s tests`.


В iOS-приложении настройки нужно передать **до создания** `WKWebView`: `configuration.allowsInlineMediaPlayback = true`, `configuration.mediaTypesRequiringUserActionForPlayback = []`. Сайт не может изменить эти настройки контейнера. В Android WebView аналогичная настройка — `webView.settings.mediaPlaybackRequiresUserGesture = false`. Проверять звук и автозапуск нужно в самом приложении; настольный браузер не воспроизводит ограничения контейнера.


Для Кинескопа кнопка запуска принимает нажатие внутри самого iframe: родительская иконка не перехватывает его. Это важно для Safari, где передача команды через `postMessage` не равнозначна прямому нажатию. После события `Playing` первый ролик снимается с начальной паузы, визуальный слой плеера открывается. Если автозапуск соседнего ролика запрещён, доступна та же кнопка вместо текстовой подсказки без рабочего действия. Иконка находится внутри активной карточки и листается вместе с ней.

Высота карточки и прокручиваемой области задана явно. Размер берётся из доступной видимой области (`visualViewport.height`, с ограничением по высоте окна); `svh` остаётся запасным вариантом. Это учитывает панели Safari и нативные окна, в которых CSS-высота может превышать видимую область. При изменении высоты во время свайпа перерасчёт откладывается до завершения прокрутки. Нижний безопасный отступ сохраняется и в портретном режиме. После завершения прокрутки лента доводится до ближайшей целой карточки; во время касания эта доводка не выполняется.
